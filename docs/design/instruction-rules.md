# Правила Инструкций

Когда пишешь или обновляешь инструкции для этого repo:

- Называть current packages и paths точно.
- Предпочитать один current example множеству generic examples.
- Не упоминать unrelated product domains.
- Future proposals помечать как proposals.
- Границы packages держать явными.
- Писать достаточно кратко, чтобы agents реально читали документ.
- Вся документация должна быть на русском языке.

Избегать stale names из copied documentation: old host paths, obsolete module aliases, old UI-kit package names и unrelated domain routes.
